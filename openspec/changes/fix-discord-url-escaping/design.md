## Root Cause

The interaction excerpt pipeline is intentionally shared by work-item comments, work-item descriptions, and direct public Page mentions. After BeautifulSoup removes HTML and replaces Plane mention nodes, `build_safe_rich_text_excerpt` calls `escape_discord_markdown` on the complete plain-text result. The current regular expression is broader than Discord's formatting needs for this context:

```text
https://plane.tmlab.top/.../254ee0b6-b92b-4493-82b9-...
                         │   │  │
                         └───┴──┴── escaped as `\.` and `\-`
```

The resulting backslashes are introduced before the Webhook request. Discord receives them as part of the Embed field value; it is not responsible for altering the Plane source comment. The separate `embed.url` value is generated by `_canonical_page_url` or `_canonical_work_item_url` and is not passed through this helper, which explains why the title link can remain correct while the quoted excerpt is malformed.

## Decision

Make the shared escape operation token-aware:

1. Identify URL-looking text tokens before Markdown escaping (at minimum `http://` and `https://` tokens bounded by whitespace or text boundaries).
2. Emit those URL tokens unchanged so valid URL punctuation remains byte-for-byte stable and Discord can auto-link the displayed text.
3. Apply the existing Markdown escaping to non-URL segments, retaining protection for backticks, emphasis markers, angle brackets, brackets, braces, pipes, and other syntax that can affect rendering or mentions.
4. Apply the existing visible-character limit after tokenization/escaping. Truncation must not leave an added escape character in front of a URL or split a URL token in a way that changes the preceding visible text contract.

This keeps the security boundary in the neutral helper: unsupported HTML is still removed, Plane mentions still become display names, and top-level Discord mentions remain controlled by `allowed_mentions`. It avoids a global Markdown policy change for unrelated fields and avoids modifying canonical destination URL builders.

## Alternatives Considered

- **Remove `.` and `-` from the global escape regex:** fixes the shown URL but still adds escapes to other valid URL punctuation such as `#`, `?`, or parentheses and weakens escaping for non-URL prose.
- **Wrap URLs in Markdown link or code syntax:** changes the displayed content and may prevent Discord's normal URL auto-linking; it also introduces another escaping surface.
- **Change Discord transport or ask Discord to normalize the field:** transport receives already malformed text, and Discord cannot infer whether a backslash was user-authored or inserted by Plane.

## Compatibility and Rollout

No database migration, configuration change, or event-key change is required. Existing cards retain their current routing, recipients, fields, and canonical links; only URL text in safe excerpts is corrected. Rollback is a code rollback or disabling the affected event selections while retaining the existing configuration.
