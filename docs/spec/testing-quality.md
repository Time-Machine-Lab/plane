# 测试与质量验证规范

## 目标

测试和验收只服务于本次需求：确认需求目标已经达到，并为实际改动提供足够的回归信心。
验证方式和范围由需求、改动位置及风险决定，不执行与需求无关的检查，也不套用固定流程链。

## 核心原则

- 实现 Agent 负责开发检查，但不能给出最终验收结论。
- 实现完成后，主 Agent 必须创建一个未参与实现的新 Tester 子 Agent，由它独立验证需求目标。
- Tester 应从需求、OpenSpec 和必要产品状态出发，不沿用实现 Agent 的验证路径，也不修改产品代码。
- 每项验证都必须能够对应到需求目标、改动风险或确有必要的相邻回归。
- 优先选择成本最低且足以证明结果的方式；本地或离线能够确认时，不部署测试环境。
- 不因单个需求运行无关的全库测试、全量构建、完整 Docker 套件或全产品验收。
- 不在不同阶段重复执行已经能够证明同一结果的检查。
- 验证场景数量按需求决定，不设置固定数量。

## 选择验证方式

实现 Agent 按改动性质选择必要的开发检查；独立 Tester 选择足以确认需求目标的最终验证方式：

- 静态检查：适用于类型、格式、配置、文档和可静态确认的契约变更。
- 受影响模块检查：适用于需要 lint、类型检查、构建或已有测试覆盖的代码改动。
- 自动化测试：适用于逻辑复杂、容易回归，或涉及权限、数据隔离、迁移、Secret、
  序列化、事件行为等风险边界的改动。
- 离线结果检查：适用于消息 Payload、模板、格式、文案、序列化结果等无需真实运行环境的改动。
- 测试环境验证：仅适用于必须依赖真实运行时、服务协作、数据库行为或用户界面交互才能确认的目标。

自动化测试按风险和回归价值决定，不是每个需求的强制项。若现有测试基础设施能够低成本覆盖关键逻辑，
应优先复用；不为一个孤立页面或低风险改动引入新的测试框架。

实现 Agent 的静态检查、现有测试和调试结果属于开发证据，不能替代独立 Tester 的目标验证。Tester 可以复用
生成结果或测试环境，但必须独立判断结果是否满足需求，不以实现 Agent 的结论作为通过依据。

## 何时使用测试环境

仅在以下情况使用测试环境：

- 本地或离线方式无法证明需求的核心行为。
- 改动依赖服务启动、数据库 migration、异步任务、跨服务调用或真实页面交互。
- 用户明确要求在测试环境中验收。

需要部署时，使用现有的 `scripts/test/deploy-test.ps1`，并只选择本次改动影响的服务。
不要为了验证一个局部改动部署无关服务，也不要重复执行部署脚本已经完成的环境准备、启动和健康检查。

纯文档、静态配置、消息格式或能够通过本地和离线结果完整确认的改动，默认不部署。

## 验证范围

验证内容仅包括：

- 本次需求明确要求的结果。
- 改动直接影响的关键行为和风险边界。
- 一条确有必要的相邻回归，用于确认改动没有破坏最接近的已有行为。

相邻回归不是固定要求。只有存在清晰的影响关系和实际回归风险时才执行。
不得扩展到无关模块、无关角色、无关页面或完整业务流程。

验证失败后，先修复导致失败的改动，再只复验失败范围和必要的相邻行为；不重新执行无关检查或完整验收。
修复由实现 Agent 完成，随后交回同一个 Tester 复验；只有 Tester 无法继续时才创建新的 Tester。

## 第三方集成

- 对 Discord、邮件、支付等外部系统的真实调用，必须得到用户明确授权。
- 未获授权时，使用 mock、离线 Payload、序列化结果或本地桩验证，不得发送真实消息或请求。
- 对卡片样式、消息结构、文案和字段格式等变更，离线结果可以作为最终验证证据。
- 只有需求目标本身包含真实连通性，且用户已授权时，才进行范围最小的真实调用。

## 结果与记录

- `pass`：已有足够证据确认需求核心目标达到。
- `fail`：验证条件可用，但实际结果与需求不一致。
- `blocked`：需求核心目标无法验证，且缺少的环境、凭据、账号或外部条件无法在当前范围内解决。

未运行无关测试、未部署不需要的服务或未执行未授权的第三方调用，均不构成 `blocked`。没有完成独立 Tester
验证表示需求尚未完成，不能标记为 `pass`，但不应伪装成环境阻塞。只有核心目标因缺少必要条件而无法得到
有效验证时，才应将变更标记为 `blocked`。

验证结果通常在任务交付说明中简要记录即可。只有以下情况才创建
`openspec/changes/<change>/verification.md`：

- OpenSpec 或用户明确要求保留验收记录。
- 变更复杂或风险较高，需要长期保存可追溯证据。
- 测试环境部署、多人验收或阻塞情况需要后续接续。

记录只需说明验证目标、采用的方法、可观察结果以及未解决风险，不使用固定模板。

## 安全约束

- 任何输出和记录不得包含密码、Token、Cookie、认证 Header、连接串、Webhook、服务器地址或私有配置。
- 测试数据应最小化，只清理本次验证创建且能够明确识别的数据。
- 不清空、重建或破坏共享测试环境，不修改与需求无关的账号、配置或数据。
- 部署和第三方调用前确认目标环境与目标范围，避免把测试行为发送到生产环境或无关频道。
- 收集日志时只保留定位问题所需的脱敏信息；结果正确时不额外检查正常成功日志。
