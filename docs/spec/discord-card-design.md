# Discord 通知卡片设计规范

本文定义 Plane Discord 通知卡片的轻量视觉基线。新增或修改 Discord 通知时，应先参考本文；事件行为、触发条件和接收人仍由对应 OpenSpec 规格定义。

## 设计目标

- 用户第一眼看清“发生了什么”和“发生在哪个对象上”。
- 任务主体、事件说明、属性和操作入口具有明确层级。
- 相同信息在不同事件中保持一致位置和表达。
- 在 Discord 桌面端和移动端都能快速扫读。

本文只约束消息展示，不引入独立设计系统、复杂组件或新的投递机制。

## 两种卡片骨架

Discord 通知只使用两种骨架。

### 单事件卡

用于任务创建、任务分配、任务完成、提及和评论等单次事件。

```text
消息正文          仅在需要 @ 成员时出现
┌────────────────────────────────────┐
│ 来源             Plane · 项目名称 │
│ 主题             事件｜任务编号 · 任务名称
│ 事件说明         谁做了什么       │
│                                    │
│ 属性栏           状态 / 优先级 / 时间
│ 补充信息         负责人或消息位置 │
│ 页脚             简短操作提示     │
└────────────────────────────────────┘
```

规则：

- `author.name` 使用 `Plane · {项目名称}` 或 `Plane · {事件类别}`。
- `title` 同时包含事件主题和任务主体，并通过 `url` 链接到准确位置。
- `description` 只用一句自然语言说明操作者和动作；评论或提及正文使用引用块。
- 属性栏最多放三个并排短字段；长文本必须独占一行。
- `footer` 只放操作提示或贴心提醒，不重复标题、项目和时间。
- `timestamp` 使用事件真实发生时间。

### 任务简报卡

用于按成员或“未分配”分组的定时任务简报。一名成员对应一条 Discord 消息，消息正文显示分组摘要，消息内每个任务使用独立 Embed。

```text
@接收人 · 日期 · 任务总数
逾期数 / 今日截止数 / 待推进数

┌─ 任务 1：红色边线，已逾期 ─────────┐
│ 项目 / 任务标题 / 属性栏 / 提醒语   │
└────────────────────────────────────┘
┌─ 任务 2：黄色边线，今日截止 ───────┐
│ 项目 / 任务标题 / 属性栏 / 提醒语   │
└────────────────────────────────────┘
┌─ 任务 3：蓝色边线，普通待办 ───────┐
│ 项目 / 任务标题 / 属性栏 / 提醒语   │
└────────────────────────────────────┘
```

规则：

- 不把多项任务塞进同一 Embed 的字段网格。
- 每个任务 Embed 的标题为 `{任务编号} · {任务名称}`，标题直接链接任务。
- 每个任务必须显示所属项目、紧急程度、状态和任务时间。
- 风险说明放在属性栏之前，例如 `已逾期 2 天` 或 `今天 18:00 截止`。
- 每个任务的贴心提醒放在该 Embed 的 `footer.text`，结尾使用“喵~”。
- Discord 单条消息的 Embed 数量和总字符数必须遵守平台限制；超限处理由任务简报的行为规格决定。

## 属性栏

属性栏统一采用已确认的“图标标签 + 灰底徽标值”样式。

| 属性 | 字段标签 | 字段值示例 |
| --- | --- | --- |
| 状态 | `📍 状态` | `🟡 \`进行中\`` |
| 优先级 | `⚡ 优先级` | `🔴 \`紧急\`` |
| 截止时间 | `⏰ 截止` | `🔴 \`今天 18:00\`` |
| 任务时间 | `🗓️ 任务时间` | `\`8 月 18 日 → 8 月 21 日\`` |
| 负责人 | `👤 负责人` | `\`Genius\`` |

属性栏规则：

- 标签图标固定表达属性类型，不随事件变化。
- 属性值使用 Discord 行内代码语法形成灰底徽标。
- 色点只表达业务语义，不作为装饰。
- 同一张卡片最多显示三个并排属性；第四项起改为独占一行或删除非关键信息。
- 不在属性栏显示 Plane User ID、Discord User ID 等系统字段。

### 色点语义

| 色点 | 语义 |
| --- | --- |
| `🔴` | 紧急、逾期、失败或需要立即行动 |
| `🟡` | 进行中、今日截止或需要关注 |
| `🟢` | 已完成、正常或成功 |
| `🔵` | 待开始、普通信息或后续处理 |
| `⚪` | 无优先级、未分配或未知状态 |

## 事件主题

事件标题使用固定语义图标和中文文案。图标用于识别事件，不在其他位置重复堆叠。

| 事件 | 标题模板 | Embed 颜色 |
| --- | --- | --- |
| 任务创建 | `🆕 新任务｜{编号} · {名称}` | Discord 蓝 `#5865F2` |
| 任务分配 | `👤 分配给你｜{编号} · {名称}` | 琥珀色 `#F0B232` |
| 任务完成 | `✅ 已完成｜{编号} · {名称}` | 绿色 `#57F287` |
| 任务逾期 | `🔴 {编号} · {名称}` | 红色 `#ED4245` |
| 提到了你 | `🔔 {操作者} 在{位置类型}中提到了你` | 紫色 `#9B59B6` |
| 新评论 | `💬 {编号} · {名称}` | 青绿色 `#1ABC9C` |

任务简报中的单项任务按风险使用红、黄、蓝色边线，不统一使用简报主题色。

## 内容规则

- 面向用户的固定文案使用中文；任务名称、项目名称和人员名称保留原始内容。
- 任务事件突出任务，人物事件突出操作者和原消息。
- 评论与提及内容使用 Markdown 引用块，并在达到事件规格规定的长度时截断。
- 链接优先放在 `title.url`，避免增加无意义的“链接”属性字段。
- 提及成员时，消息 `content` 使用 `<@DISCORD_USER_ID>`；Embed 内不生成可触发的提及。
- `allowed_mentions.parse` 必须为空，`allowed_mentions.users` 只包含本次明确通知的映射用户。
- 不依靠 Markdown 表格、代码块、连续空格或空字段实现布局。
- 不重复信息：标题已经表达事件时，正文不再复述同一句话。

## 新事件接入检查

新增 Discord 通知事件时，只需确认以下事项：

1. 选择“单事件卡”或“任务简报卡”骨架。
2. 确定中文标题模板、语义图标和 Embed 颜色。
3. 选择最多三个关键属性，并按本规范使用图标标签和徽标值。
4. 确定准确的标题链接、接收人和允许提及名单。
5. 在桌面端和移动端确认主题突出、字段不拥挤、长文本不破坏布局。

未在本文覆盖的行为不要扩充这份视觉规范，应在对应 OpenSpec change 中说明。
